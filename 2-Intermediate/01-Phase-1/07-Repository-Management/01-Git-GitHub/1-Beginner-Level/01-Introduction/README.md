# Introduction to Git and GitHub

## What is Version Control?
Version control is a system that records changes to a file or set of files over time so that you can recall specific versions later. It allows you to revert files to a previous state, revert the entire project to a previous state, compare changes over time, see who last modified something, and more.

## What is Git?
Git is a **distributed version control system**. This means that every developer's computer has a full copy of the project history, not just the files. If the server dies, any client repository can restore the full timeline.

## What is GitHub?
GitHub is a **hosting platform** for Git repositories. It provides a web-based interface and adds collaboration features like:
- **Pull Requests**: Propose changes and get code reviews.
- **Issues**: Track bugs and feature requests.
- **Actions**: Automate testing and deployment (CI/CD).
- **Projects**: Manage project boards (Kanban/Sprint).

## Key Concepts
- **Repository (Repo)**: The folder where your project lives.
- **Commit**: A snapshot of your project at a specific point in time.
- **Branch**: A parallel version of your repository. Use branches to work on features without affecting the main code.
- **Merge**: Combining changes from one branch into another.
- **Clone**: Downloading a copy of a repository from a remote server (like GitHub).
- **Push/Pull**: Uploading your changes (Push) or downloading others' changes (Pull).
