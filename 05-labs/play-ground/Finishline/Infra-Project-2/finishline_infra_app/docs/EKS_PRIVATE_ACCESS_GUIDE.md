Before using the SSH tunnel, ensure you have:

   ```bash

   cd terraform/envs/dev
   terraform output jumphost_public_ip
   ```

2. **SSH private key** (generated by Terraform)
   ```bash

   ls -la terraform/modules/key_pair/finishline-infra-key-pair.pem
   ```

3. **kubectl installed locally**
   ```bash
   kubectl version --client
   ```

4. **AWS CLI configured**
   ```bash
   aws sts get-caller-identity
   ```

## Method 1: SSH Tunnel (Recommended for Daily Use)

### Step 1: Establish SSH Tunnel

```bash
# Set variables (update with your values)
JUMPHOST_IP=$(cd terraform/envs/dev && terraform output -raw jumphost_public_ip)
KEY_FILE="terraform/modules/key_pair/finishline-infra-key-pair.pem"
EKS_API_ENDPOINT=$(aws eks describe-cluster \
  --name finishline-infra-eks-cluster \
  --query 'cluster.endpoint' \
  --output text)

# Extract the hostname without https://
EKS_HOST=$(echo $EKS_API_ENDPOINT | sed 's|https://||')

# Establish tunnel (keep this terminal open)
ssh -i "$KEY_FILE" \
  -N \
  -L 443:$EKS_HOST:443 \
  ec2-user@$JUMPHOST_IP

# Tunnel is now active on localhost:443
```

**Explanation of SSH flags:**
| Flag | Purpose |
|------|---------|
| `-i` | SSH key file |
| `-N` | No remote command (tunnel only) |
| `-L` | Local port forwarding |
| `443:$EKS_HOST:443` | Forward localhost:443 to EKS:443 |

### Step 2: Configure kubectl to Use Tunnel

```bash
# In a NEW terminal (keep tunnel running)
export KUBECONFIG=$(pwd)/kubeconfig-tunnel

# Update kubeconfig to use localhost
aws eks update-kubeconfig \
  --name finishline-infra-eks-cluster \
  --region us-east-1

# Edit kubeconfig to point to localhost
sed -i 's|https://[a-zA-Z0-9.-]*\.gr7\.us-east-1\.eks\.amazonaws\.com|https://localhost:443|g' $KUBECONFIG

# Verify connectivity
kubectl get nodes
kubectl get pods -A
```

### Step 3: Verify Cluster Access

```bash
# Should show 2 Ready nodes (per assignment §79)
kubectl get nodes

# Expected output:
# NAME                                        STATUS   ROLES    AGE   VERSION
# ip-10-0-4-1.ec2.internal                    Ready    <none>   5m    v1.31.x
# ip-10-0-5-1.ec2.internal                    Ready    <none>   5m    v1.31.x
```

### Step 4: Clean Up

```bash
# When done, close the SSH tunnel terminal
# Press Ctrl+C in the tunnel terminal

# Remove temporary kubeconfig
rm $KUBECONFIG
```

For operations that don't require local kubectl:


```bash

```

## Method 3: Temporary Public Access (Emergency Only)

⚠️ **Use only for emergency troubleshooting**, then disable immediately.

### Step 1: Enable Public Access Temporarily

```bash
cd terraform/envs/dev

# Edit terraform.tfvars
nano terraform.tfvars
# Change: endpoint_public_access = true

# Apply change
terraform apply -target=module.eks -auto-approve
```

### Step 2: Update kubeconfig Locally

```bash
aws eks update-kubeconfig \
  --name finishline-infra-eks-cluster \
  --region us-east-1
```

### Step 3: Verify and Immediately Disable

```bash
kubectl get nodes  # Verify it works

# Then IMMEDIATELY disable public access
cd terraform/envs/dev
nano terraform.tfvars
# Change back: endpoint_public_access = false
terraform apply -auto-approve
```

**⚠️ Never leave public access enabled in production!**

## Troubleshooting

### Issue: Tunnel Connection Refused

**Symptom:**
```
kubectl get nodes
Unable to connect to the server: dial tcp [::1]:443: connect: connection refused
```

**Causes:**
1. SSH tunnel not running
2. Wrong port in tunnel command

**Fix:**
```bash
# Verify tunnel is running
ps aux | grep "ssh.*-L 443"

# If not running, re-establish tunnel
ssh -i "$KEY_FILE" -N -L 443:$EKS_HOST:443 ec2-user@$JUMPHOST_IP
```

---

### Issue: Kubeconfig Points to Wrong Endpoint

**Symptom:**
```
kubectl get nodes
x509: certificate signed by unknown authority
```

**Fix:**
```bash
# Regenerate kubeconfig
aws eks update-kubeconfig \
  --name finishline-infra-eks-cluster \
  --region us-east-1 \
  --kubeconfig ./kubeconfig-tunnel

# Update to localhost
sed -i 's|https://[a-zA-Z0-9.-]*\.gr7\.us-east-1\.eks\.amazonaws\.com|https://localhost:443|g' ./kubeconfig-tunnel

# Verify
cat ./kubeconfig-tunnel | grep server:
# Should show: server: https://localhost:443
```

---

### Issue: SSH Permission Denied

**Symptom:**
```
ec2-user@<ip>: Permission denied (publickey)
```

**Causes:**
1. Wrong key file
2. Key permissions too open

**Fix:**
```bash
# Fix key permissions
chmod 400 terraform/modules/key_pair/finishline-infra-key-pair.pem

# Verify key name matches what's in AWS
aws ec2 describe-key-pairs --key-name finishline-infra-key-pair
```

---

### Issue: EKS Cluster Not Found

**Symptom:**
```
An error occurred (ResourceNotFoundException) when calling the DescribeCluster operation: No cluster found for the name: finishline-infra-eks-cluster
```

**Causes:**
1. Wrong AWS region
2. Cluster not deployed yet

**Fix:**
```bash
# Verify region
aws configure get region

# List clusters in us-east-1
aws eks list-clusters --region us-east-1

# If empty, deploy cluster first
cd terraform/envs/dev
terraform apply -auto-approve
```

## Security Best Practices

### 1. Tunnel Lifecycle

| Action | Frequency |
|--------|-----------|
| Open tunnel | When needed for kubectl access |
| Close tunnel | Immediately after use |
| Rotate SSH key | Every 90 days or if compromised |

### 2. Jumphost Hardening

The jumphost is your **only entry point** — protect it:

```hcl
# terraform.tfvars
home_ip_cidrs = ["<YOUR_HOME_IP>/32"]  # Restrict SSH to your IP only
```

**Never use `0.0.0.0/0`** except for initial testing.

### 3. Monitor Access

Enable CloudTrail logging for EKS API calls:

```hcl
# In EKS module
cluster_enabled_log_types = ["api", "audit", "authenticator"]
```
