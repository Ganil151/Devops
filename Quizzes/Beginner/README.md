## 🏗️ Real-World Scenarios (Beginner)

**Scenario S1: The "It Works on My Machine" Problem**
A developer says their new feature works perfectly on their laptop, but it fails when deployed to the testing server because the server is missing a specific library. 
**Question**: Which DevOps tool/concept best solves this consistency problem?
- A) Git
- B) Docker (Containerization)
- C) SSH
- D) Manual Documentation

**Scenario S2: The "Accidental Deletion"**
You are working on a collaborative project and accidentally deleted a critical configuration file on your local machine. You haven't pushed your latest changes yet, but the file was part of previous commits.
**Question**: Which Git command allows you to restore that specific file from the last commit?
- A) git init
- B) git status
- C) git checkout -- <filename>
- D) git push

**Scenario S3: The "Slow Release"**
Your team takes 2 days to manually test and deploy a new version of your web app every time a small bug is fixed. The management wants updates to be faster and less error-prone.
**Question**: What should the team implement to automate this process?
- A) A better SSH key management system
- B) A CI/CD Pipeline
- C) More Linux servers
- D) A private Docker registry

**Scenario S4: The "Connection Refused" Mystery**
A developer is trying to access a web server running on a Linux VM via port 80, but they keep getting a "Connection Refused" error. The server process is confirmed to be running and listening on all interfaces.
**Question**: What is the first thing a DevOps engineer should check in the cloud console?
- A) The VM's CPU usage
- B) The Security Group / Firewall rules for inbound traffic
- C) The DNS registration of the domain
- D) The Docker version on the VM

**Scenario S5: The "Permissions Denied" Mystery**
A new intern tried to upload a file to a specific storage bucket but received an "Access Denied" message. They have an IAM user but haven't been assigned to any groups or given any direct permissions.
**Question**: Based on the principle of "Deny by Default," why can't they upload the file?
- A) Because they aren't using a VPN
- B) Because in cloud environments, no permissions are granted until explicitly allowed by a policy
- C) Because the storage bucket is full
- D) Because the intern doesn't have an email address

**Scenario S6: The "YAML Syntax Error"**
A developer is trying to deploy a Kubernetes manifest but gets a "mapping values are not allowed in this context" error. They look at the file and see that one line has 3 spaces of indentation while the rest of the block has 2.
**Question**: What is the primary cause of this failure?
- A) YAML is case-sensitive, and they used a capital letter.
- B) YAML relies on strict white-space indentation to define structure, and inconsistent spacing breaks the parser.
- C) They forgot to add a semicolon at the end of the line.
- D) Semicolons are required in YAML.
