# Database Security Best Practices

A complete guide to securing relational and NoSQL databases in the cloud, with a focus on defense-in-depth and automated monitoring.

## 1. Identity & Access Management for Databases

Traditional username/password authentication is prone to credential leakage. Modern cloud databases support IAM-based authentication.

### IAM Database Authentication (RDS)
Allows you to connect to your DB instance using an IAM role or user instead of a password.
- **Benefits**: Credentials are short-lived (15 mins), centralized management, no hardcoded passwords.
- **How it works**: Uses an **Authentication Token** generated by AWS STS.

#### Example: Connecting to MySQL with IAM
1. Enable IAM Authentication on the RDS instance.
2. Create an IAM policy allowing `rds-db:connect`.
3. Generate the token:
```bash
TOKEN=$(aws rds generate-db-auth-token \
    --hostname my-db.xyz.us-east-1.rds.amazonaws.com \
    --port 3306 \
    --region us-east-1 \
    --username db_user)

# Connect using the token as password
mysql --host=my-db.xyz.us-east-1.rds.amazonaws.com \
      --port=3306 \
      --user=db_user \
      --password=$TOKEN --enable-cleartext-plugin
```

## 2. Encryption Strategies

### Encryption at Rest (KMS)
- Always enable encryption during DB creation.
- Use **Customer Managed Keys (CMK)** instead of AWS Managed Keys for better control and auditing of who can access the key.
- Encrypt backups and snapshots automatically.

### Encryption in Transit (SSL/TLS)
- Enforce SSL/TLS for all connections.
- Set the `require_secure_transport` parameter in RDS Parameter Groups (for MySQL/MariaDB/PostgreSQL).
- Download and use the AWS Global Bundle public key to verify the DB certificate.

## 3. Network Security (The Perimeter)

### Private Subnets
- Databases should **NEVER** have a public IP address.
- Place DBs in private subnets with no route to the Internet Gateway.

### Security Group Hardening
- Only allow inbound traffic on the DB port (e.g., 3306 or 5432) from specific application Security Group IDs.
- **NEVER** allow `0.0.0.0/0`.

```hcl
# Terraform Example: Restrictive DB Security Group
resource "aws_security_group" "db_sg" {
  name        = "rds-security-group"
  vpc_id      = var.vpc_id

  ingress {
    from_port       = 3306
    to_port         = 3306
    protocol        = "tcp"
    security_groups = [aws_security_group.app_sg.id] # Only from app
  }
}
```

## 4. Monitoring & Auditing

### Database Activity Streams
Monitor every query executed against your database.
- Integrates with Amazon Kinesis for real-time analysis.
- Useful for compliance (SOX, PCI-DSS) and detecting SQL injection.

### Vulnerability Scanning
- Use **Amazon GuardDuty** for RDS to detect suspicious login patterns (e.g., brute force attacks).
- Enable **RDS Enhanced Monitoring** and Export Logs to CloudWatch.

## 5. Security Hacks & Performance Tips

### The "read-only" Account Hack
Always create a separate `read_only` user for reporting and analytics tasks. This limits the "blast radius" of human errors or SQL injection in reporting dashboards.

### Automated Patching
Enable "Auto Minor Version Upgrade" to ensure security patches are applied during the maintenance window without manual intervention.

## Summary Checklist
- [ ] Use IAM Authentication instead of static passwords where possible.
- [ ] Enforce SSL/TLS for all data in transit.
- [ ] Place databases in isolated private subnets.
- [ ] Implement query logging and audit trails.
- [ ] Rotate administrative passwords regularly (using Secrets Manager).
