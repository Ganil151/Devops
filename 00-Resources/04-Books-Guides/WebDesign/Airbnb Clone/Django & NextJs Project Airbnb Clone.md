#### Remove Dangling Images (Most Common "Children" to Remove)
Dangling images are the most immediate candidates for removal as they are untagged layers that are no longer part of a named image.
1. **List Dangling Images (Optional, but Recommended to See What Will Be Removed):**        
```bash
docker images -f "dangling=true"
```
This command will show you all images that have `<none>:<none>` for their `REPOSITORY` and `TAG`.
2. **Remove All Dangling Images:**
   
```bash
docker image prune
```
This command will prompt you for confirmation before proceeding. Type `y` and press Enter.
_To bypass the confirmation prompt (use with caution):_
```bash
docker image prune -f
```
#### **Option 2: Remove All Unused Images (More Aggressive Cleanup)**
This option removes _all_ images that are not associated with any running container, including dangling images and images that might have a tag but are no longer in use.
1. **List All Unused Images (Optional):** There isn't a direct filter to list "all unused" images explicitly, as `dangling=true` only shows untagged ones. However, you can use `docker images -a` to see all images and then mentally identify those you know are not in use.
2. **Remove All Unused Images (including dangling ones):**
```bash
docker image prune -a
```
This command will prompt you for confirmation. Type `y` and press Enter.
_To bypass the confirmation prompt (use with caution):_
```bash
docker image prune -a -f
```
#### **Option 3: Comprehensive System Cleanup (Most Aggressive)**

The `docker system prune` command is the most comprehensive way to free up disk space. It removes:
- All stopped containers
- All networks not used by at least one container
- All dangling images
- All dangling build cache
1. **Perform a System Prune (excluding volumes):**
```
docker system prune
```
This will prompt for confirmation.
2. **Perform a System Prune (including volumes):**    
- **Use with extreme caution!** This will remove _all_ local volumes that are not used by at least one container. If you have persistent data in anonymous volumes that you want to keep, **do not use this command without understanding its implications.** Named volumes are generally safer from this command if they are still referenced.
```
docker system prune --volumes
# or the most aggressive, often used for a clean slate:
docker system prune -a --volumes
```
These commands will also prompt for confirmation. 
_To bypass confirmation (use with extreme caution):_ 
```
docker system prune -a -f --volumes
```
### **Important Considerations:**
- **Running Containers:** Docker will _not_ remove images that are currently being used by a running container. You must stop and remove the container first if you want to delete its associated image.
- **Build Cache:** `docker system prune` is excellent for clearing the build cache, which can accumulate many intermediate layers.
- **Production Environments:** In production, be very careful with `prune` commands, especially `-a` and `--volumes`. It's generally better to have a clear strategy for image lifecycle management and use specific `docker rmi <image_id_or_name>` commands or carefully crafted filters.
- **Specific Image Removal (`docker rmi`):** If you want to remove a specific image by its ID or name/tag, and it's not referenced by a running container, use:
```bash
docker rmi <image_id_or_name>
# Example: docker rmi my_old_image:v1.0
# Example: docker rmi 123abc456def (image ID)
```
